The dashboard documents mapped waterlogging locations across Kanpur and Gurugram. Each entry records the source citation, event date, reported rainfall figure, and documented data limits.

Missing records do not imply safety; unlisted roads may still flood under heavy rain.

Archived reports often cite district-wide totals, approximate timeframes, or qualitative news accounts rather than street-level telemetry. Because public data is partial, the absence of a record does not prove that a road stays dry.

05 / System architecture

Independent data pipelines.

The browser dashboard presents historical event records. The Python risk engine processes incoming rainfall telemetry against configured roads. The two pipelines remain separate to preserve clear data lineage.

06 / Scope and limits

Documented constraints.

  1. i.

    Uncertified prototype.

    Garuda Route is an experimental dashboard. It does not replace official flood advisories, municipal road closures, or emergency response guidance.

  2. ii.

    Unmonitored roads are unverified.

    Missing entries remain unmapped rather than marked clear. Stale sensor telemetry indicates communication delays rather than receding water.

  3. iii.

    Live weather feeds require authorized access.

    Accessing IMD district telemetry requires valid agency credentials. Without active keys, the feed reports offline rather than assuming clear skies.

  4. iv.

    Route checks reflect mapped incidents only.

    Path evaluation compares journeys against logged flooding points. The system does not simulate drain capacity, runoff velocity, terrain elevation, or river cresting.

07 / Begin

Run it in a minute.

Terminal
$ git clone https://github.com/SG4067/garuda-route.git
$ cd garuda-route
$ node backend/server.js
# then open http://127.0.0.1:3000

Node.js 18 or newer. The web server uses built-in modules, so no root-level install is needed. Google Maps and IMD access are configured separately.
